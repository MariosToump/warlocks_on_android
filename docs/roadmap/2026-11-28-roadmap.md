# Lava Warlocks roadmap (planning, 2026-11-28)

The user, 2026-11-28: "From now, I don't want you to make any changes on the code because there are a lot of stuff
that we need to discuss, make some plans about." This file collects every topic they raised. Each topic gets its own
brainstorm and spec (`docs/superpowers/specs/`) before any code. Nothing here is decided until the user says so.
Items marked **(proposal)** are Claude's suggestions.

## Standing rule: performance first (the user, 2026-11-28)
"Have performance as a top priority at all times, like FPS drops, and stress testing should be at utmost
importance ... it should even run on a toaster."
- Every feature, effect or mode is checked against the stress test (`tools/perf_stress.gd`, the
  phone-performance-check skill) before it counts as done. Budgets: `docs/perf/BASELINE.md`.
- The low-end target device is the Android 8 phone from the perf pass (**proposal**: also a cheap 2 GB phone and an
  old laptop with integrated graphics).
- **Proposal:** a "Low" graphics option (no shimmer, fewer embers and sparks) as a safety net, plus a frame-time
  check in the test suite that fails if a scene gets much slower than the baseline.

## Topics (no fixed order yet; suggested order at the end)

### A. Multiplayer (the user: "the very first thing that this game is about")
What exists: wizards are driven by a controller node (`PlayerController` for you, `AIController` for bots). A
network controller can drive a wizard the same way, which helps. The game logic uses randomness (about 40 calls), so
the safest model is one machine deciding the game (the host or a server) and the others sending inputs and showing
the result.
Questions for the brainstorm:
1. Who plays together: friends with an invite or room code, strangers through matchmaking, or both?
2. Phone and PC in the same match (cross-play)?
3. How many players: 4, and later 8? Bots filling empty seats?
4. Online only, or local Wi-Fi (LAN) too?
5. Is paying for a server OK (roughly a few euros a month to start), or should it be free, with one player
   hosting?

Options to compare later:
- Godot's built-in ENet, with a player hosting. Free and simple, but needs port forwarding or a relay.
- A small dedicated server (headless Godot on a cheap VPS). Fair and needs no port forwarding, but has a monthly
  cost.
- WebRTC. Peer to peer, needs a signalling server, and works in browsers.
- Steam networking (GodotSteam). PC/Steam only, so phones would still need one of the above.

Hard parts:
- Lag on fast projectiles and knockback (prediction and rollback, or input delay).
- Cheating, if a player hosts.
- Reconnecting, the shop phase, and the ghost.
- Testing: a harness that runs 4 headless clients.

**Decided by the user (2026-11-28):**
- Room codes for friends, **and** matchmaking with random people online, in casual and ranked. Matchmaking is "the
  major thing".
- ~~Phone and PC in the same matches.~~ **Changed 2026-11-28: no cross-play.** "Android version will be Android version, PC version will be PC version", in casual and ranked alike ("mouse with a thumb makes a huge difference"). Separate player pools and queues. The same server software can run both pools. Open: may friends on different platforms share a private room code? (proposal: no for now, to keep it simple)
- A dedicated server: "we definitely need a server".
- **Match format (2026-11-28):** free-for-all, as the game is now (4 warlocks, first to 3 round wins), in casual and ranked. Team modes (2v2, 4v4) are an option for later. Ranked points then come from placement (1st-4th).
- **Queue while you play (2026-11-28):** from the start, a player can be in training mode or a bot match and queue
  for any online mode (casual or ranked) at the same time. When a match is found, a pop-up appears: **Accept** or
  **Decline**. "That's how I want this to continue."
  - Claude's reading: no bots fill online seats, and the queue waits for real players. Correct this if wrong.
  - Proposals:
    - The pop-up has a ~15 s timer and a sound plus vibration, so it's noticed mid-fight.
    - Accepting ends the offline match at once.
    - If someone declines or times out, the others go back to the front of the queue. The decliner gets a short
      queue cooldown only after repeated declines.
    - The menu shows "Searching... 1:23" and the number of players in the queue.

#### Servers: options and costs (researched 2026-11-28; verify prices before buying)
How much a match needs is a guess until measured. Lava Warlocks is a small 2D game: 4-8 players, a few dozen moving
things. A headless Godot server for one match should take a small share of one CPU core and roughly 50-100 MB of
memory. So a cheap 2-CPU / 4 GB server might run roughly 10-30 matches at once (about 40-120 players). We'll measure
this with a load test before trusting it (performance-first rule).

| Stage | Option | Cost | What you get | Safety | Capacity |
|---|---|---|---|---|---|
| Now (friends) | One cheap VPS (Hetzner, ~€5-6/month for 2 vCPU / 4 GB, after its 2026 price rise), running a headless Godot game server plus our own small lobby (room codes + quick-match queue) | ~€6/month | Full control, one region (EU) | We patch it, plus a firewall. The server decides the game, so players can't cheat by editing their copy | Tens of matches (to be measured) |
| Growing (hundreds of players) | **Nakama** (open source, free to self-host on the VPS: accounts, matchmaking, ranked ratings, leaderboards, Godot SDK) + **Edgegap** for match servers near the players (says free under ~100 players online / 1,000 a day for indies, then ~$0.026 per vCPU-hour) | ~€10-50/month | Matchmaking + ranked done properly, servers in many regions, low lag worldwide | Nakama has accounts and security built in; Edgegap isolates each match | Hundreds to thousands online |
| Professional (thousands+) | AWS GameLift (from ~$0.09-0.11/hour per server + data; FlexMatch matchmaking), Heroic Cloud (managed Nakama, reported from ~$600/month), Edgegap or Gameye at scale | Hundreds+ per month, grows with players | Autoscaling, global regions, support | DDoS protection, professional ops | Very large |

Notes:
- **Vendor risk is real.** Hathora (shut down May 2026) and Unity Multiplay (deprecated 2026) both closed this year.
  **Proposal:** package the game server as a Docker container, so it can move between the VPS, Edgegap and GameLift
  without rewriting.
- **Ranked needs accounts.** Options are Steam login on PC, Google Play Games login on Android, or Nakama's own
  account or device ID. Ranked also brings GDPR (personal data) and anti-cheat (the server decides everything).
- **Safety basics at every stage:**
  - the server decides the game, and clients send only inputs;
  - rate limits;
  - no free-text chat;
  - automatic security updates;
  - backups of the ranked database.

### B. Training mode
"Some descriptions or maybe a bit of training mode that someone can test different type of stuff, skill,
knockbacks."
- **Proposal:** a practice arena with:
  - a dummy target that you can set to stand still, walk, or cast back;
  - every spell unlocked and its level adjustable;
  - free gold, no lava damage (optional), and a reset button;
  - a damage, knockback and distance readout for each hit;
  - short spell cards (what it does, combos, counters), taken from the shop descriptions.
- Question: should first-time players be steered into it, or is it purely optional?

### C. Better menus and an intro (inspiration: Dead Cells)
- A title or intro sequence, a main menu (Play, Training, Multiplayer, Settings, Feedback, Credits), and more
  consistent menus throughout.
- Dead Cells' main menu is a live, animated scene behind a short vertical list of options, with strong pixel art
  and quick transitions. **Proposal:** the arena idles behind the menu, with bots fighting softly and lava moving,
  under a short list. That's cheap, because the scene already exists.
- Question: what do you like most in Dead Cells' menu (the live background, the music, the speed, the layout)?

### D. Visual transitions and effects
- "A fade in before a fight starts to come from the left, and disappearing from the right."
- **Proposal:** a wipe transition (pixel or diagonal) between title, shop and fight, with the round banner in the
  middle. It's one shader or `ColorRect` that all screens use, and it's cheap on phones.
- This ties in with todo 0 (graphics and design) and the visual-review findings.

### F. In-game feedback
"Players can send us feedback at some point, what they feel, how it is."
- **Proposal:**
  - a Feedback button in the pause and results screens;
  - a 1-5 "fun" rating plus a free-text box;
  - it sends the game version, platform and match stats, with no personal data.
- Ways to receive it:
  - A Google Form or Tally link opened in the browser. Simplest, with no server.
  - A Discord webhook. Easy, but the key ends up inside the game.
  - A small endpoint on the future multiplayer server.
- Privacy: if anything that identifies a person is stored (email, IP address), the GDPR applies, and a privacy policy
  is needed. That's needed for Google Play anyway.

### I. Legal and store steps (a separate full review before publishing)
Starting points found 2026-11-28 (not legal advice; check the official pages and a local accountant or lawyer):

**Google Play**
- A one-time $25 account fee and an identity check.
- Personal accounts made after Nov 2023 must run a closed test with at least 12 testers opted in for 14 days in a
  row before going public. Organisation accounts appear to be exempt, but that's unofficial.
- You need:
  - a privacy policy URL, even with no data collected;
  - the Data safety form;
  - the content-rating questionnaire (IARC);
  - the current target API level.
- EU Digital Services Act "trader" status must be declared. Third-party sources say the deadline is February 2027.
  If you sell or monetise, you're probably a trader, and your contact address and phone number are shown to EU
  users. Many solo developers use a business or virtual address for this.

**Steam**
- $100 per game (Steam Direct), paid back from sales after $1,000 of revenue. Valve takes a 30% cut.
- Onboarding takes 1-5 days: identity check, bank details, and a tax form (for non-US developers, a W-8BEN with
  treaty rate).
- A "Coming Soon" store page is needed at least 2 weeks before release, and both the store page and the build are
  reviewed.

**Everywhere**
- **Name:** run a trademark search on the game's name ("Lava Warlocks"; the Android app is called "Warlocks on
  Android") in EUIPO / TMview and USPTO. Avoid names and art from the Warcraft III map. Game mechanics themselves
  are not protected.
- **Licences:**
  - check that the PixelLab plan allows commercial use;
  - check that the music and sound sources allow commercial use;
  - include the Godot MIT licence notice in the credits.
- **Tax:** earning money from sales usually means registering as self-employed or as a business where you live.
  The stores collect VAT for customer sales in most countries, but your income tax is your own.
- **Multiplayer and feedback:** they bring GDPR duties (IP addresses, any accounts). Free-text chat brings
  moderation and age-rating questions, so **proposal:** use emotes or quick-chat, not free chat.
- **Age rating:** IARC on Play. Steam has its own content survey.
- Todo 11: a private code repo plus an "All rights reserved" notice.

## Suggested order (proposal, for the user to change)
1. **Multiplayer brainstorm first, design only.** Its answers shape the menus (lobby, room codes), training
   (offline practice), feedback (server or form) and 8-warlock mode. Building menus before that risks redoing them.
2. **itch.io page + a simple feedback link (E + F).** This brings real feedback early and needs almost no game code.
3. **Menus + intro + transitions (C + D)**, designed with the multiplayer screens in mind.
4. **Training mode (B).**
5. **Multiplayer build (A)**, in steps: local network test, then online, then cross-play.
6. **Loadouts, balance, gold, then 8 warlocks (G + H).**
7. **Legal review + stores (I, todo 17)**, when it's close to a real release.
Throughout: performance first, using the stress test on the low-end phone for every step.
